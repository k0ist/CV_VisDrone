# Обнаружение транспорта и пешеходов на снимках с БЛА (VisDrone, YOLO26)

Научно-исследовательская работа: экспериментальное исследование детектора YOLO26 на аэросъёмке (датасет VisDrone-DET). Основные вопросы работы:

- как входное разрешение (640 / 960 / 1280) влияет на качество обнаружения малых объектов;
- помогает ли дополнительная детекционная голова P2 (шаг 4) и её укороченный вариант P2–P4;
- какую роль играет перенос предобученных весов в модели с изменённой архитектурой.

> **Статус: работа в процессе.** Часть экспериментов ещё обучается (см. раздел «Статус и планы»). Таблицы ниже обновляются по мере завершения запусков.

## Данные

[VisDrone-DET](https://github.com/VisDrone/VisDrone-Dataset): train 6471, val 548, test-dev 1610 изображений, 10 классов (pedestrian, people, bicycle, car, van, truck, tricycle, awning-tricycle, bus, motor). Кадры около 2000×1500 пикселей. В val **68,6 % объектов малые** (< 32×32), 28,7 % средние, 2,8 % крупные. Данные в репозиторий не входят, ноутбук скачивает и конвертирует их в формат YOLO автоматически (нужно соблюдать условия использования датасета).

## Модели

Все модели масштаба `s` (Ultralytics 8.4.183).

| Модель | Описание | Параметры (слитая) | GFLOPs (на 640) |
|---|---|---|---|
| База | YOLO26s, уровни P3–P5 | 9,47 млн | 20,8 |
| P2–P5 | штатный `yolo26-p2.yaml`, уровни P2–P5 | 9,43 млн | 24,6 |
| P2–P4 | свой вариант: P2–P5 без уровня P5 | 6,87 млн | 22,5 |

P2–P4 получается из штатного P2-конфига удалением трёх слоёв ветки P5 (Conv, Concat, C3k2) и исключением этого входа из `Detect`. Ноутбук создаёт оба YAML автоматически (раздел 2б).

**Перенос весов.** Для P2-моделей из `yolo26s.pt` переносятся слои 0–16 (backbone и верхняя часть шеи); остальное инициализируется случайно. Дополнительно реализован перенос «по ролям» слоёв: слои 23 и 25 в P2–P4 по форме совпадают со слоями 17 и 19 базы. Перенос проверяется по форме и равенству тензоров, при несовпадении запуск останавливается.

## Результаты (val, 548 изображений)

Метрики Ultralytics (best.pt); AP по размерам считается pycocotools (maxDets=1000).

| Модель | Вход | mAP50 | mAP50-95 | AP small | Условия |
|---|---|---|---|---|---|
| База | 640 | 0,402 | 0,233 | 0,139 | Colab, 1 GPU, seed 0 |
| P2–P5 | 640 | 0,406 | 0,235 | 0,146 | Kaggle, 2×T4 (DDP), seed 0 |
| P2–P4 | 640 | 0,401 | 0,233 | 0,148 | Kaggle, 2×T4 (DDP), seed 0 |
| База | 1280 | **0,558** | **0,345** | **0,253** | Kaggle, 2×T4 (DDP), seed 0 |
| P2–P4 | 1280 | 0,522 | 0,317 | 0,231 | Kaggle, 2×T4 (DDP), seed 0 |

Влияние инициализации (база, 640, Kaggle, seed 1, различается только перенос весов):

| Запуск | mAP50-95 | AP small |
|---|---|---|
| База, веса перенесены целиком | 0,231 | 0,138 |
| База, перенесены только слои 0–16 | 0,220 | 0,130 |

Скорость инференса на 640 (Kaggle T4, `val` на одной карте): база 5,2 мс, P2–P4 8,2 мс, P2–P5 9,7 мс на кадр.

### Что видно

- **Разрешение даёт самый большой эффект:** переход с 640 на 1280 поднимает mAP50-95 с 0,233 до 0,345, а AP малых объектов почти вдвое. Цена: ≈ вчетверо больше вычислений.
- **Неполный перенос весов стоит ≈ 0,011 mAP50-95** (в сравнении выше). Голова P2 при равной инициализации даёт порядка +0,013–0,015 (P2–P5 против базы с тем же частичным переносом, разные seed), поэтому на 640 эти эффекты почти взаимно гасятся.
- **P2–P4 на 1280 пока хуже базы** (0,317 против 0,345). Причина не установлена полностью: кандидаты — инициализация, меньший батч на карту у P2–P4 (по 1 снимку против 2) и малая польза P2 при уже достаточном разрешении.
- **Разброс между запусками.** Два запуска базы на 640 (разные seed и среды) отличаются на 0,0015 mAP50-95. Это одна пара, поэтому различия порядка ±0,002 считать значимыми нельзя. По AP крупных объектов (их ≈ 1000) разброс гораздо больше.

### Ограничения

- База на 640 обучалась в Colab на одной карте (batch 16), остальные запуски на Kaggle в режиме DDP (общий batch делится между двумя T4). Батчи по запускам: 16 для 640, 4 для базы на 1280 и 2 для P2–P4 на 1280. Статистика BatchNorm считается по меньшему числу снимков на карту.
- В большинстве запусков один seed.
- Подбор параметров проводится только по val; test-dev запускается один раз для финальных моделей.

## Воспроизведение (Kaggle)

Ноутбук: [`01_train_eval_kaggle_v2.ipynb`](01_train_eval_kaggle_v2.ipynb).

**Окружение.** Kaggle Notebook, акселератор **GPU T4 ×2**, **Internet On** (скачиваются `ultralytics==8.4.183`, веса `yolo26s.pt` и датасет). Для длинного обучения используйте *Save Version → Save & Run All*: ноутбук выполняется в фоне (сессия до 12 ч).

**Порядок ячеек:** окружение → конфигурация → (синхронизация с Google Drive) → датасет → функции переноса весов → создание конфигов P2 (только для P2-моделей) → обучение → кривые → валидация → режим без NMS → AP по размерам. Ячейка теста на test-dev по умолчанию отключена.

**Конфигурация** (всё меняется в одной ячейке):

| Параметр | Назначение |
|---|---|
| `MODEL` | `yolo26s.pt` (база), либо путь к `configs/yolo26s-visdrone-p2.yaml` / `...-p2-p4.yaml` |
| `PRETRAINED` | `"yolo26s.pt"` для переноса весов в P2-конфиг, `None` для базы |
| `PRETRAINED_MAX_LAYER` | переносить слои `0..N` (по умолчанию 16) |
| `ROLE_MAP` | перенос слоёв по ролям: P2–P4 `{23: 17, 25: 19}` |
| `IMGSZ`, `BATCH` | разрешение и общий batch (при DDP делится между картами) |
| `SEED`, `EPOCHS` | воспроизводимость и длительность |
| `USE_DDP` | обучение на двух GPU; `False` для одной |
| `RUN_SUFFIX` | суффикс имени запуска; у каждого запуска должен быть уникальным |

Рецепт: SGD, `lr0=0.01`, 50 эпох, `close_mosaic=10`, AMP.

**Обучение на двух GPU (DDP).** Ultralytics перезапускает процессы по имени модели, поэтому веса, перенесённые в объект, при DDP терялись бы. Ноутбук сохраняет модель с перенесёнными весами в `*_init.pt` и стартует обучение из него.

**Синхронизация с Google Drive (необязательно).** Результаты в `/kaggle/working` пропадают после сессии, поэтому ноутбук выгружает прогресс на Google Drive через rclone каждые 10 минут и может продолжить обучение после обрыва. Нужен секрет Kaggle `RCLONE_TOKEN` (токен, выданный командой `rclone authorize "drive"`); не публикуйте его.
